# Test content

Known-good media used to validate ingest workflows. This is not pytest code
(`tests/`) and not runtime recordings (`data/`).

Drop clips here, then point a **file** channel or `scripts/capture_test.py`
at the path. In Docker the directory is mounted at `/test-content`.

## Layout

```
test-content/
  mpegts/          MPEG-TS files for file ingest and capture smoke tests
```

When you add a clip, record its properties in the catalog below. Do not
silently replace a fixture with a different container, codec, or PID layout.

## Catalog


| File                   | Container | Video                         | Audio | Duration | Notes                                      |
| ---------------------- | --------- | ----------------------------- | ----- | -------- | ------------------------------------------ |
| `mpegts/sample.ts`     | MPEG-TS   | H.264, 640×360, 25 fps, ~800 kbps | none  | 5 s      | Generated by `capture_test.py --mode file` |


`mpegts/sample.ts` is created on first file-mode capture test if it is missing.
It is a `videotestsrc` → `x264enc` (`tune=zerolatency`) → `mpegtsmux` clip.

## Use

```bash
# Pipeline-only file ingest (generates mpegts/sample.ts if needed)
docker compose --profile gst run --rm gst python scripts/capture_test.py --mode file

# File channel URI inside Compose
#   /test-content/mpegts/sample.ts
# Same file on the host
#   test-content/mpegts/sample.ts
```

Media files under this directory are gitignored (they can be multi-GB). Keep
the catalog in this README up to date so local clips stay documented. Runtime
recordings still belong under `data/`.
